Flights Tracker

Un vigilante personal de precios de vuelos que funciona íntegramente en GitHub y gratis: escanea mis destinos cada día, encuentra el día más barato para volar y me envía por correo solo las ofertas que de verdad merecen la pena.

El problema

Los precios de los vuelos pueden variar cientos de euros entre fechas contiguas, y «una tarifa barata» no significa nada si no se sabe cuánto cuesta normalmente la ruta. Los servicios de alertas o te llenan de avisos por bajadas insignificantes o exigen una cuenta, un servidor y una suscripción. Yo quería algo que vigilara mi propia lista de destinos, me avisara cuando un precio es realmente bajo y no costara nada mantener.

Cómo funciona

Un workflow programado de GitHub Actions consulta una API de precios de vuelos para cada destino de config.json, para cada fecha de los próximos meses, con la duración de viaje que fijo por país: un fin de semana, un número fijo de noches o un rango. Los resultados se guardan en una base de datos de histórico de precios que persiste entre ejecuciones en la caché de Actions, y el mismo workflow regenera la web y la publica en GitHub Pages. No hay servidor, ni inicio de sesión, ni una máquina siempre encendida.

La web es HTML, CSS y JavaScript puros, sin dependencias. Muestra el día más barato de una ciudad o de un país entero como gráfico de precio por día, una vista de exploración para recorrer destinos y la planificación de puentes alrededor de los festivos españoles. Los filtros funcionan como en un metabuscador: escalas, duración, hora de salida, aerolíneas que evitar, con orden por más barato, mejor o más rápido.

Qué cuenta como un chollo

Una tarifa solo se destaca cuando es baja en relación con la ruta, no solo en términos absolutos. Tres niveles seleccionables comparan el precio con el coste habitual de la ruta, con la posición de la fecha dentro de su propio periodo y con las fechas cercanas, para que la temporada baja normal no se confunda con una oferta. El nivel más estricto exige un precio al menos un 40 % por debajo de lo normal, dentro del 5 % de fechas más baratas y al menos un 25 % por debajo de los días vecinos.

Para que el correo siga siendo útil, hay un único resumen al día con como máximo una oferta por destino, y un destino no se vuelve a destacar durante 14 días salvo que aparezca algo al menos un 10 % más barato. El resumen sale a las 8:00 hora de Madrid a través de una issue de GitHub que me menciona, de modo que son las propias notificaciones de GitHub las que entregan el correo: sin servidor de correo ni credenciales que mantener.

Decisiones técnicas

  • Todo en GitHub. Actions para programar y calcular, Pages para el alojamiento, una issue para el correo y la caché para el estado. Coste cero y nada que mantener encendido.
  • Ajustes sin backend. Los cambios hechos en la web abren una issue de GitHub ya rellenada; un segundo workflow la aplica a config.json y vuelve a escanear. El propio repositorio es la base de datos y el panel de administración.
  • Proveedores de precios intercambiables. Un proveedor real (Travelpayouts) y uno de demostración con precios simulados comparten una misma interfaz, así que la app y las pruebas funcionan sin clave de API, y el modo demo está claramente señalado en la interfaz.
  • Un catálogo de 195 países y sus aeropuertos, con duraciones de viaje, límites de escalas y supuestos de equipaje por país.
  • Lógica principal probada. La detección de ofertas, las reglas antispam y la gestión de la configuración están cubiertas por pruebas automáticas que se ejecutan en CI en cada push.

Límites reales

Las API de precios no indican qué equipaje incluye una tarifa, así que la app lo estima a partir de la aerolínea y lo dice. El descuento de residente del 75 % en vuelos domésticos de Canarias y Baleares también es una estimación. Las tarifas proceden de una API de precios en caché y no de los sistemas en vivo de las aerolíneas, por lo que son una señal fiable pero no una garantía. Las capturas de aquí usan el modo demo simulado de la app, no tarifas reales.
