WildCast

A daily wildlife-encounter forecast: for a place and a date, a ranked, calibrated list of species you're likely to see — grounded in real sighting data, not a guess.

Try it live ↗View on GitHub ↗Design doc ↗

Problem

"What am I actually likely to see if I go to this place, on this day?" is a question every wildlife trip runs into, and most answers to it are guesswork — a blog post, a guide's gut feeling, a generic "best season" claim with no numbers behind it. WildCast turns it into an actual forecast: pick a place and a date, and get species ranked by a calibrated probability of encounter, each with a plain-language reason grounded in real data — season, that day's weather, how much real evidence backs the claim, and (where available) conservation status and the species' own activity pattern.

Technical decisions

The backend pulls real occurrence data from GBIF, iNaturalist and eBird, real historical weather and climate normals from Open-Meteo, and optionally real IUCN Red List conservation status — no invented statistics anywhere in the pipeline. A scikit-learn HistGradientBoostingClassifier is trained on that data and calibrated with sigmoid scaling (a real failure mode surfaced while building this: isotonic calibration with few folds once inverted a species' entire seasonal curve, scoring summer below winter for a species that should never show that pattern — caught by testing a concrete, checkable claim rather than just "did it return a number").

Every prediction ships with a deterministic, template-based "why" explanation built from real numbers already in the model bundle — not an LLM call — so every sentence traces back to a figure you could look up yourself. Ten pilot areas across ten biomes (Yellowstone to Svalbard to the Amazon) ship pre-trained; an Explore Anywhere mode extends this live to any point on Earth, checking all 50 curated species against real GBIF/iNaturalist/eBird presence within a radius of the clicked point before scoring anything, and honestly labels the approximation it's making (nearest pre-trained area's model, real distance shown) rather than hiding it.

The frontend is a single-file, installable Progressive Web App — no build step, works offline for the app shell, and never caches live predictions so real vs. demo data can't go stale and mislabeled. The whole thing ships through Docker and a GitHub Actions CI/CD pipeline (lint, 178+ tests, Docker build, all confirmed green on GitHub's own runners), with a weekly scheduled workflow that re-fetches real GBIF/weather data and commits it back to the repo.

Real production issues, found and fixed

Three real bugs surfaced from actual use rather than code review, each with a regression test pinning the fix:

  • A 502 under load. Fetching GBIF, iNaturalist and eBird evidence sequentially let their timeouts sum — once eBird was configured live, a single bird-species request could exceed the server's 30-second worker timeout. Fixed by fetching all three sources concurrently and raising the timeout as extra headroom.
  • False-positive sightings. A lion and leopard showed up as "verified" near Bangkok — zoo photos, not wild ones. Excluding GBIF's captive-specimen record types caught the institutional case but not a casual zoo photo posted to iNaturalist, since both carry the same metadata tag as a real wild sighting. The actual fix: gate every species' live query to its own hand-checked list of plausible countries, so the query structurally can't return a country the species doesn't live in.
  • Overconfident predictions on thin evidence. A user's own framing of the bug: "if there is a species in an area, but there are barely sightings, you cannot have a high probability." A leopard near one point in Thailand was showing 91% confidence backed by 500 sightings — borrowed from its curated home area (Kruger, South Africa), unrelated to that exact point. Fixed by scaling probability against the real local sighting count within the search radius, using a square-root curve so thin evidence is penalized hard without needing hundreds of local records just to stop being penalized at all.

Result

A working, tested, deployable app: real multi-source data, a calibrated model, an installable PWA frontend, and a test suite (178+ unit and integration tests) that checks specific directional claims — grizzly bears score higher in July than January, kangaroos higher in a Brisbane winter than summer — not just "did the endpoint return 200." Accounts, favorites and saved-search alerts run on free, stdlib-only infrastructure (SQLite locally, Turso in production over plain HTTPS) to keep the whole project free to run, by design.

Honest limits

Explored anywhere on Earth, but still gated to the 50 curated species — true "any species, anywhere" needs live species discovery near a point, flagged as a real next step rather than built silently around. Catalog scale (10 areas, 50 species) is deliberately bounded rather than rushed to hundreds, since curating each species' plausible-country list by hand is real natural-history work, and rushing it multiplies the error surface without a corresponding increase in care.
