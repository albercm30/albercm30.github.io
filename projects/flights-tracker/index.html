Flights Tracker

A personal flight-price watcher that runs entirely on GitHub, for free: it scans my destinations every day, finds the cheapest day to fly, and emails me only the deals that are actually good.

Open the app ↗View on GitHub ↗

Problem

Flight prices swing by hundreds of euros between neighbouring dates, and "a cheap fare" is meaningless without knowing what the route normally costs. Alert services either spam you with marginal drops or need an account, a server and a subscription. I wanted something that watches my own list of destinations, tells me when a price is genuinely low, and costs nothing to run.

How it works

A scheduled GitHub Actions workflow queries a flight-price API for every destination in config.json, for every date in the next months, using the trip length I set per country: a weekend, a fixed number of nights, or a range. Results go into a price-history database that persists between runs in the Actions cache, and the same workflow regenerates the site and publishes it to GitHub Pages. There is no server, no login and no always-on machine.

The web app is plain HTML, CSS and JavaScript with no dependencies. It shows the cheapest day for a city or a whole country as a price-per-day chart, an explore view for browsing destinations, and long-weekend planning around Spanish bank holidays. Filters work like a metasearch: stops, duration, departure time, airlines to avoid, sorted by cheapest, best or fastest.

What counts as a bargain

A fare is only highlighted when it is low relative to the route, not just low in absolute terms. Three selectable levels compare the price with the route's usual cost, with how the date ranks in its own period, and with the dates around it, so ordinary low season isn't mistaken for a deal. The strictest level wants a price at least 40% under normal, in the cheapest 5% of dates and at least 25% below neighbouring days.

To keep the email useful, there is one digest a day with at most one deal per destination, and a destination isn't highlighted again for 14 days unless something at least 10% cheaper appears. The digest goes out at 8:00 Madrid time through a GitHub issue that mentions me, so GitHub's own notifications deliver the email: no mail server or credentials to run.

Technical decisions

  • Everything on GitHub. Actions for scheduling and compute, Pages for hosting, an issue for the email, and the cache for state. Zero cost and nothing to keep running.
  • Settings without a backend. Edits made in the web app open a pre-filled GitHub issue; a second workflow applies it to config.json and rescans. The repository itself is the database and the admin panel.
  • Pluggable price providers. A real provider (Travelpayouts) and a demo provider with simulated prices share one interface, so the app and tests run without an API key, and the demo mode is clearly labelled in the UI.
  • A catalogue of 195 countries and their airports, with per-country trip lengths, stop limits and baggage assumptions.
  • Tested core logic. The deal detection, anti-spam rules and config handling are covered by automated tests that run in CI on every push.

Honest limits

Price APIs don't say which baggage a fare includes, so the app estimates it from the airline and says so. The 75% resident discount for Canary and Balearic domestic flights is likewise an estimate. Fares come from a cached-price API rather than live airline systems, so they are a strong signal rather than a guarantee. The screenshots here use the app's simulated demo mode, not real fares.
