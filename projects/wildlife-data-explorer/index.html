Wildlife Data Explorer

A personal data platform connecting wildlife encounters, locations, dives, trips and photography — and the actual engine behind the Wildlife, Diving and Travel pages on this site.

Problem

Years of trips produce the same problem every time: photos in one place, GPS coordinates nowhere, species names half-remembered, and no way to answer a simple question like "what have I actually seen, and where?" without scrolling through a camera roll. I wanted a single structured dataset that could answer that — and render itself as a map, not just a spreadsheet.

Technical decisions

Every sighting, dive and trip lives as a record in a JSON dataset — species, location, coordinates, date, and links back to the country and dive site it belongs to — rather than in prose, so the same data can drive a map, a filterable list and future statistics without re-entering anything. Python handles the cleanup and validation pass over that data before it ships.

The maps themselves run on Leaflet with OpenStreetMap tiles rather than an embedded third-party map widget, which keeps the styling fully in the site's own colour palette and lets each marker carry custom data — a hand-built div icon sized by encounter count, with a popup built from the same JSON record. Because everything is static JSON rather than a live database, the whole site still ships as plain files on GitHub Pages with no backend to run.

Result

The dataset currently backs three live pages — Wildlife, Diving and the country archive under Travel — with 200+ species records and 19 logged dives, each plotted on its own interactive map with custom markers and popups.

Next steps

The clearest next step is cross-linking: clicking a country in the archive should be able to surface the dives and sightings logged there, since the underlying data already has enough shared structure (coordinates, country, date) to join across the three datasets — it just isn't wired together in the UI yet.
