Invoice Recognition

A document AI workflow that turns scanned receipts and invoices into structured, queryable data.

Problem

Receipts and invoices arrive as images or scanned PDFs — useful to a person, useless to a database. Finance and reporting workflows need the same information (amounts, dates, payment status, whether a document is a duplicate of one already logged) as structured fields, and manually re-keying that data is slow and error-prone at any real volume.

Technical decisions

The pipeline combines OCR to pull raw text off the document image with rule-based and model-based parsing to map that text onto structured fields — vendor, amount, date, line items — since invoice layouts vary enough between vendors that a single fixed template doesn't generalise. On top of extraction, I built two specific detectors: one for payment status (has this invoice already been paid, based on associated text and metadata) and one for duplicate documents, comparing extracted fields and text similarity against previously processed invoices rather than relying on exact file matches, since the same invoice is often re-uploaded in a slightly different scan or format.

This was built as a proof-of-concept for prospective clients, so a priority alongside accuracy was making the output easy to demo — a clear before/after showing a messy scanned document turning into a clean structured record in seconds.

Result

The proof-of-concept was used directly in client-facing demonstrations by the AI team, showing the full path from raw scanned document to structured, duplicate-checked data without manual re-entry.

Next steps

The obvious next layer is handling a wider variety of real-world document quality — skewed scans, phone photos, partially obscured text — and adding confidence scoring per field so low-certainty extractions get flagged for review instead of silently accepted.
